# 机器人导航系统坐标系分析报告

## 当前坐标系使用情况分析

### 1. SLAM模块 (build/slam/)
- **坐标系：** 使用自定义的毫米级坐标系
- **位置表示：** `Position`类，x_mm, y_mm, theta_degrees
- **初始坐标：** 地图中心设为 `500 * map_size_meters` 毫米
- **角度表示：** 使用度数制，范围内转换

### 2. AMCL模块 (build/amcl/)
- **坐标系：** 使用粒子滤波器坐标系
- **坐标变换：** 
  - `pf_vector_coord_add`: 局部坐标转全局坐标
  - `pf_vector_coord_sub`: 全局坐标转局部坐标
- **角度处理：** 弧度制，自动标准化到[-π, π]

### 3. TEB模块 (build/teb/)
- **坐标系：** 使用复杂的坐标系转换系统
- **转换函数：**
  - `GXtGY(double x)`: 坐标翻转转换
  - `GXtMX(double x)`: 全局坐标转地图坐标
  - `GYtGX(double y)`: Y坐标转换
- **角度处理：** 弧度制，包含复杂的角度调整（如 `-PI/2`）

### 4. NAV模块 (build/nav/)
- **坐标系：** 使用像素坐标系统
- **地图尺寸：** 800x800像素
- **坐标范围：** 整数坐标，从(0,0)到(800,800)

## 问题识别

### 1. 坐标系不统一
- SLAM使用毫米级浮点坐标系
- AMCL使用粒子滤波器浮点坐标系
- TEB使用复杂的多级坐标系转换
- NAV使用像素级整数坐标系

### 2. 角度表示不一致
- SLAM使用度数制
- AMCL/TEB使用弧度制
- 坐标原点定义不统一

### 3. 数据流传递问题
- 各模块间的坐标系转换复杂
- 缺乏统一的坐标变换节点
- 容易产生累积误差

## 解决方案设计

### 1. 标准坐标系定义
```
map (全局坐标系)
  ↕ 
base_link (机器人本体)
  ↕ 
laser (激光雷达)
  ↕
odom (里程计)
```

### 2. 位姿融合匹配节点设计
- **输入：** SLAM位姿、AMCL位姿、IMU数据、里程计
- **处理：** 卡尔曼滤波/扩展卡尔曼滤波融合
- **输出：** 统一的机器人位姿估计

### 3. TF树维护节点设计
- **功能：** 统一坐标系变换管理
- **维护：** base_link, map, odom, laser等frame关系
- **发布：** 标准TF坐标变换消息

## 实施优先级
1. 实现TF树维护节点（基础）
2. 实现位姿融合匹配节点（核心）
3. 更新各模块集成新节点
4. 测试和优化系统性能
